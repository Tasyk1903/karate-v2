# KarateRating: единый scope оставшихся работ

Обновлено 17.09.2026 после подтверждения владельцем приёмки ученика, тренера, судьи и web организатора/секретаря. Проверенные рабочие маршруты, сетки/ката/видео, контрольные выгрузки и внешний вид удалены из scope. Это подтверждение владельца, не новый автоматический прогон. Устройство, переиспользуемая логика и фактические проверки: [карта проекта](project-guide.md#scope-verification).

Закрытые задачи удалены, а не оставлены зачёркнутыми. Не создавать дополнительные отчёты. Проверку на тестовом API нельзя называть сквозной проверкой рабочего приложения; автоматические тесты не заменяют согласование внешнего вида владельцем.

**Кабинет ученика:** 17.09.2026 владелец сообщил о завершении ручной приёмки, отдельный scope удалён по его запросу. Карта кода и проверок находится в [Student mobile](project-guide.md#student-mobile). Общие внешние зависимости ученика сохранены ниже вместе с зависимостями тренера; они не считаются настроенными по результату визуальной приёмки.

## 1. Внешние зависимости

- [ ] **MOB-AUTH-DISTRIBUTION / P1. Ссылки установки общего приложения.** Владелец должен предоставить реальные URL App Store/Google Play либо TestFlight/тестового распространения. Настроить `MOBILE_APP_IOS_URL` / `MOBILE_APP_ANDROID_URL`, затем проверить письмо Coach/Student → установка/открытие актуальной сборки → нативная регистрация с кодом организации/тренера → подтверждение email → вход. Письма и нативные формы реализованы; ссылок пока нет, пустые кнопки/выдуманные адреса не подставляются. Изменения Flutter требуют новой сборки, старое приложение продолжит открывать web-регистрацию.

Это **не только визуальная проверка**. Для push ещё нужна интеграция, для оплаты нужны тестовые ключи. Перенос файлов в приватный S3 завершён, включая учебные материалы; доказательства и исторические исключения находятся в [карте проекта](project-guide.md#storage-s3).

- [ ] **MOB-PROFILE-06 / P1. Push: конфигурация и интеграция.** Нужны Firebase/APNs для bundle `ru.karaterating.karateratingTrainer`; конфигурационные файлы в проектах не найдены. После предоставления конфигурации реализовать нативное разрешение, регистрацию/обновление токена устройства, очередь доставки, отписку при выходе/удалении и безопасный переход после проверки сессии/согласий. Затем проверить на устройстве foreground/background/terminated. В текущем этапе доставка push не реализована; не показывать фиктивный рабочий переключатель. Для нового workflow обязательны аудит без секретов и permission-тесты.

- [ ] **MOB-PAY-QA / P1. Sandbox ЮKassa.** Проверка эффективной конфигурации 17.09.2026: shop ID/API key заполнены, ключ имеет префикс `live_`, APP_URL локальный (`http://localhost:8080`). Это не sandbox; для безопасной проверки подключить именно тестовый магазин и его ключ, публичный HTTPS callback `/api/payment-callback` и APP_URL. Пройти оплату, отмену, callback и возврат на физическом устройстве на отдельном онлайн-турнире с открытой записью без сгенерированных таблиц. Ключи не присылать в чат и не записывать в документацию. Код оплаты проверен с подменённым gateway; при диагностике запросы к провайдеру и списания не выполнялись.

- [ ] **STU-PAY-QA / P1. Два платёжных сценария ученика.** После настройки sandbox из MOB-PAY-QA пройти собственную онлайн-ката и оплату учебного разбора: оферта, оплата/отмена, задержанный и повторный callback, закрытие приложения, возврат и конечный статус. При конфликте не повторять списание; решение о возврате принимает оператор. Разбор до очереди мастера также проверяется в JM-PAY-QA.

- [ ] **STU-MAIL-QA / P1. Доставка регистрационного/reset/restore письма.** На разрешённом тестовом адресе пройти регистрацию с кодом тренера и подтверждением email, сброс пароля и восстановление самостоятельно удалённого аккаунта. Проверить доставку/спам, локаль, истёкший и повторно использованный код. Подменённая почта в автотестах не подтверждает реальную доставку.

## 2. Серверные зависимости после запуска

- [ ] **DEPLOY-CAPACITY / P1. Диск и резервные копии.** После развёртывания свободно около 2.8 GiB из 48 GiB. Увеличить диск перед активным использованием, настроить внешний бэкап новой Docker MySQL и проверить восстановление в отдельном окружении. Текущий локальный архив старого checkout защищает от ошибки переключения, не от потери сервера. Удаление данных чужих проектов для освобождения места не разрешено.

## 3. Мастер

Приёмка мастера и решение об административном назначении/переназначении работ остаются в [judge-master-scope.md](judge-master-scope.md). Владелец подтвердил судью и тренера, но пока не подтвердил мастера. Общие push и оплата не считаются завершёнными вместе с приёмкой интерфейса.

## 4. Повторная проверка исправлений

- [ ] **STU-JOIN-COACH-QA / P1. Присоединение без регистрации.** На актуальной мобильной сборке: прежний тренер открепляет ученика → ученик открывает профиль → «Присоединиться к тренеру» → код → имя/клуб → подтверждение. Проверить удобство на своём телефоне и обновление профиля без выхода. Серверные и widget-проверки сохранности аккаунта/документов/истории, запрета смены до открепления и ошибок выполнены, описаны в карте проекта; реальные рабочие аккаунты автоматически не переносились.

- [ ] **ADMIN-LANDING-QA / P1. Лендинг и кабинет супер-администратора.** На своём аккаунте `super_admin` проверить новую ленту/модерацию, обучение, организации, регионы/масштабы и журнал old/new с поиском «Кто изменил / Кому изменили». Проверить внешний вид лендинга по последнему референсу `94fb61fd-a5ab-421a-af79-40cab00e39b3.png` и админки на своём телефоне. Перед публикацией проверить актуальность заданных владельцем чисел 3000+/50+/40+/4+, иллюстрации экранов и утверждения макета о push/учебных форматах (push ещё требует MOB-PROFILE-06); дать реальные адреса социальных сетей для прямых ссылок вместо открытия контактов. Backend/браузерная автоматизация описаны в карте проекта; браузерный API подменён. Миграция и web-сборка уже применены локально, учётные данные не менялись.

- [ ] **ADMIN-AGREEMENTS-CONTENT / P1. Утверждённые тексты RU/EN.** Заполнить и проверить обе редакции трёх договоров в новой админке. Существующие русские тексты сохранены, юридически значимый перевод автоматически не сочинялся. Пока EN отсутствует, чтение использует RU; сохранение через новый редактор требует оба текста. Публикация новой редакции потребует повторного согласия пользователей. Ссылки установки приложения на лендинге зависят от MOB-AUTH-DISTRIBUTION выше.

- [ ] **STU-REGISTRATION-UX / P1. Первичная анкета ученика.** На актуальной сборке пройти новую регистрацию по коду тренера: email-подтверждение → автоматический вход → согласия → анкета без документов и отчества → профиль. Проверить удобство формы на своём телефоне и возврат к незавершённой анкете после перезапуска. Backend и Flutter-проверки автоматизированы; реальную доставку письма проверять вместе с STU-MAIL-QA. Существующие ученики не направляются в анкету повторно.

- [ ] **ORG-PROFILE-MOBILE / P1. Профиль ученика на телефоне.** После сообщения владельца 17.09.2026 исправлены блоки кумитэ/ката/рекорда и связь фото/реквизитов/подтверждения документов. Браузерная проверка на подменённых данных описана в карте проекта. Организатору повторно открыть свой пример ученика на телефоне: нет сжатых блоков, у каждого фото свои подписи и статус, сведения экзамена отдельно. Остальную принятую web-панель повторно проверять не требуется.

## Критерий закрытия

После ручной приёмки убрать проверенный пункт или сузить его до конкретного дефекта. При обнаружении дефекта сначала добавить воспроизводимый тест и исправление в существующий сервис/компонент. Не объявлять настроенными внешние сервисы или восстановленными файлы на основании зелёного suite. Секреты, реальные письма, платежи и изменения общей базы не использовать для автоматической приёмки.
